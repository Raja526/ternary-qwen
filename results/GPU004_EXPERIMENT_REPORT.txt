GPU004 IMPLEMENTATION
---------------------
GPU004 introduced a PyTorch nn.Module wrapper around the frozen GPU003
CUDA operator.

Persistent representation:

packed 2-bit ternary codes
+
FP16 reconstruction scales

The wrapper:
- accepts CUDA FP16 activation tensors
- preserves arbitrary leading activation dimensions
- flattens activations to 2-D for the CUDA operator
- invokes the frozen GPU003 packed CUDA operator
- restores the original leading dimensions
- supports optional bias
- keeps packed codes and scales as registered buffers

GPU004 also introduced an atomic runtime loader.

Loader phases:

Phase 1:
validate every selected checkpoint entry and original model target

Phase 2A:
construct every CUDA packed replacement module

Phase 2B:
install replacements only after all validation and construction succeeds

Therefore validation/construction failure does not partially mutate the
model.

FULL-MODEL EXACTNESS INTERPRETATION
----------------------------------
GPU003 directly isolated the selected packed operator and established
bit-exact arithmetic against frozen OPT006.

GPU004 full-model validation executes the surrounding model on different
devices:

Reference:
CPU

Candidate:
CUDA

Therefore ordinary FP16 CPU-vs-CUDA numerical differences outside the
three selected packed operators can cause full-model logit differences.

For this reason GPU004 does NOT claim full-model bit-exactness between
CPU and CUDA.

The full-model comparison is used as a CUDA integration and behavioral
correctness gate.
